# HackAlem AI — Event Match

Адаптивный фронтенд для хакатон-задачи «Умный подбор event-подрядчиков в Казахстане».

Пользователь указывает город, дату, формат мероприятия, категорию подрядчика и бюджет. Интерфейс отправляет запрос в FastAPI и показывает до трёх рекомендованных подрядчиков с объяснением «Почему подходит».

## Состав проекта

| Файл | Назначение |
| --- | --- |
| `index.html` | Интерфейс, стили и JavaScript в одном файле |
| `README.md` | Запуск, контракт API и подключение бэкенда |

Бэкенд разрабатывается отдельно. В этом фронтенде нет встроенного алгоритма подбора, модели ИИ или демоданных. Доступность подрядчиков и объяснения рекомендаций определяет сервер.

## Технологии

- HTML5, CSS3 и JavaScript без фреймворков.
- Tailwind CSS через CDN.
- Fetch API для запросов к FastAPI.
- Встроенные SVG-иконки.

Сборка и установка npm-пакетов не требуются. Основные стили также описаны обычным CSS: интерфейс сохраняет оформление, если CDN недоступен.

## Возможности

- Тёмная тема с индиго-акцентами и адаптация к мобильным экранам.
- Выбор города, даты, формата мероприятия, категории и бюджета на одного подрядчика.
- Состояния ожидания, загрузки, результата, пустой подборки и ошибки.
- Блокировка формы на время запроса и повторная отправка после ошибки.
- Отображение максимум трёх карточек в порядке, заданном бэкендом.
- Поддержка предупреждений в `message` и `status_message`.
- Выделенное объяснение `explanation` для каждой рекомендации.
- Проверка обязательных полей и положительного целого бюджета.
- Ограничение ожидания ответа до 45 секунд.
- Безопасное отображение серверного текста через `textContent`.

## Локальный запуск

Для просмотра интерфейса можно открыть `index.html` в браузере. Для совместной работы с бэкендом удобнее запуск через локальный HTTP-сервер.

1. Откройте папку проекта в VS Code и запустите терминал.
2. Запустите сервер статических файлов.

   На Windows с установленным Python:

   ```powershell
   py -m http.server 5500
   ```

   Если команда `py` недоступна, используйте `python -m http.server 5500` или `python3 -m http.server 5500`, в зависимости от установки Python.

3. Откройте [http://localhost:5500](http://localhost:5500).
4. Отдельно запустите бэкенд по его инструкции. По умолчанию фронтенд обращается к `POST http://localhost:8000/match`.
5. Заполните форму и нажмите «Подобрать».

Без работающего бэкенда интерфейс откроется, а попытка подбора покажет сообщение об ошибке подключения.

## Подключение FastAPI

Адрес запроса находится в скрипте внутри `index.html`:

```javascript
const API_URL = 'http://localhost:8000/match';
```

Если бэкенд работает на другом адресе, замените значение `API_URL`, сохранив путь к его endpoint.

### Запрос

Метод: `POST`. Заголовок: `Content-Type: application/json`.

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "event_type": "свадьба",
  "category": "Ведущий",
  "budget_kzt": 500000
}
```

- `date` передаётся как `YYYY-MM-DD`. Внешний вид поля даты зависит от языка браузера.
- `event_type` передаётся в нижнем регистре.
- `budget_kzt` — число в тенге, максимальный бюджет на одного подрядчика.
- `category` — одна выбранная категория.

### Ответ

Пример структуры ответа, а не готовая рекомендация из датасета:

```json
{
  "message": "Показан 1 доступный кандидат.",
  "cards": [
    {
      "anon_name": "Пример подрядчика",
      "category": "Ведущий",
      "city": "Алматы",
      "price_from_kzt": 450000,
      "explanation": "Объяснение соответствия параметрам пользователя, сформированное бэкендом."
    }
  ]
}
```

`cards` должен быть массивом, в том числе при отсутствии совпадений:

```json
{
  "status_message": "На выбранную дату подходящих подрядчиков нет.",
  "cards": []
}
```

Поля `message` и `status_message` необязательны. Если сервер передал оба, интерфейс покажет оба сообщения, исключив точные повторы. Если карточек больше трёх, отображаются первые три.

При отсутствующей или некорректной цене выводится «Цена уточняется». Если сервер не передал объяснение, интерфейс сообщает об этом.

### CORS для локальной разработки

В существующем приложении FastAPI добавьте middleware после создания объекта `app`:

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:5500",
        "http://127.0.0.1:5500",
    ],
    allow_credentials=False,
    allow_methods=["POST"],
    allow_headers=["Content-Type"],
)
```

Эта настройка рассчитана на запуск фронтенда через HTTP-сервер на порту 5500. Открытие файла через `file://` обычно создаёт origin `null`, который в примере выше не разрешён. Используйте локальный HTTP-сервер вместо добавления `null` в список разрешённых адресов.

Для размещённого в интернете фронтенда добавьте его точный origin в `allow_origins`. Документация: [FastAPI CORS](https://fastapi.tiangolo.com/tutorial/cors/).

## Параметры и датасет

Исходный CSV содержит 66 анонимных профилей. Для работы фронтенда загружать CSV в браузер не нужно: его обрабатывает бэкенд.

- Города: Алматы, Астана и Зарубежье.
- Даты календаря: **23.09.2026–31.12.2026**. Эти границы заданы в поле даты.
- Форматы: свадьба, той, корпоратив, конференция, юбилей и день рождения.
- В форме доступны 10 категорий из ТЗ. Датасет содержит и другие категории.
- Значения в `categories`, `event_formats`, `languages` и `busy_dates` разделены символом `|`.
- В CSV поле называется `categories`, а в карточке ответа API ожидается `category`.
- `price_imputed`, `city_imputed` и `synthetic` — признаки подготовки данных. Фронтенд не интерпретирует их самостоятельно.

Бэкенд должен проверять город, включение выбранной категории и формата в соответствующие списки, бюджет и отсутствие выбранной даты в `busy_dates` до формирования рекомендаций.

### Сценарий для демонстрации

| Параметр | Значение |
| --- | --- |
| Город | Алматы |
| Дата | 2026-10-15 |
| Формат | Свадьба |
| Категория | Ведущий |
| Бюджет | 900000 ₸ |

В предоставленном CSV этим условиям соответствуют три профиля: Мицури Канроджи, Эмилия и Кики. Их порядок и объяснения задаёт бэкенд.

При бюджете **500000 ₸**, который установлен в форме по умолчанию, и остальных параметрах из таблицы точных совпадений нет. Это подходящий сценарий для проверки пустой подборки.

## Проверка интеграции

1. Убедитесь, что в запросе передаются все пять полей и бюджет является числом.
2. Проверьте ответы с нулём, одним, двумя и тремя кандидатами.
3. Передайте `message` или `status_message` и проверьте плашку над результатами.
4. Проверьте, что во время запроса форма заблокирована, а после ответа снова доступна.
5. Остановите бэкенд и убедитесь, что появляется сообщение об ошибке и кнопка повтора.
6. Измените параметры после успешного подбора: предыдущая подборка должна исчезнуть.

Фронтенд проверен в Chromium с тестовыми ответами API, включая запуск через `file://` и ширины экрана 390, 768 и 1440 пикселей. Совместную проверку с реальным бэкендом нужно выполнить после его подключения.

## Размещение в интернете

Для общего доступа к рекомендациям нужны размещённый фронтенд и доступный ему бэкенд. В `API_URL` укажите публичный HTTPS-адрес бэкенда. На опубликованном сайте `localhost` означает компьютер посетителя, поэтому не подходит для подключения к серверу другого участника команды.

Ключи ИИ-сервиса должны храниться на бэкенде. Для браузерного интерфейса они не нужны.

## Первый коммит на GitHub

Следующие команды рассчитаны на новую локальную папку проекта и новый пустой репозиторий на GitHub. Если команда уже использует существующий репозиторий, сначала клонируйте его и добавляйте фронтенд в согласованную папку.

1. Создайте пустой репозиторий, например `hackalem-event-match`, без автоматического добавления README, `.gitignore` и лицензии. Готовый README уже находится в проекте.
2. Положите `index.html` и `README.md` в одну папку и откройте терминал в ней.
3. Выполните команды:

   ```bash
   git init
   git add index.html README.md
   git commit -m "Add event matching frontend and README"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/hackalem-event-match.git
   git push -u origin main
   ```

   Замените `YOUR_USERNAME` на свой логин. Если название репозитория другое, замените и его. Можно скопировать полный HTTPS-адрес репозитория с GitHub.

Если Git сообщает, что имя и email автора не заданы, выполните команды в папке проекта и повторите `git commit`:

```bash
git config user.name "YOUR_NAME"
git config user.email "YOUR_EMAIL"
```

Укажите своё имя и email, связанный с GitHub, либо адрес `noreply` из настроек аккаунта. Для отправки изменений потребуется настроенная авторизация GitHub.

После следующих изменений:

```bash
git add index.html README.md
git commit -m "Update event matching frontend"
git push
```

`git commit` сохраняет изменения в локальной истории, а `git push` отправляет коммиты на GitHub.

Инструкция: [Добавление локального проекта на GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).
